# save-my-wallet

내 돈은 소중하니까.

기간과 총액을 정하면 오늘 쓸 수 있는 돈을 알려주는 가계부입니다.
계정으로 로그인해 쓰고, 여행 갈 때는 초대 코드로 같이 가는 사람과 하나의 가계부를 함께 씁니다.

---

## 비용

**전부 무료입니다. 카드 등록도 필요 없습니다.**

| 구성 | 쓰는 것 | 비용 |
| --- | --- | --- |
| 앱 배포 | GitHub Pages | 무료 (공개 저장소) |
| 로그인 | Firebase Authentication (이메일/비밀번호) | 무료 |
| 데이터 저장·실시간 동기화 | Cloud Firestore (Spark 플랜) | 무료 |

Firebase의 **Spark 플랜은 결제 수단을 등록하지 않는 무료 플랜**이라서,
한도를 넘어도 요금이 청구되는 일이 없습니다. 한도를 넘으면 그날 요청이 거부될 뿐입니다.
즉 "모르는 사이에 돈이 나가는" 경우가 구조적으로 생기지 않습니다.

Spark 플랜의 Firestore 하루 한도는 대략 읽기 5만 건 / 쓰기 2만 건 / 저장 1GiB입니다.
10명이 여행 하나를 함께 기록해도 하루 수백 건 수준이라 한도의 1%도 쓰지 않습니다.
(한도는 Firebase 요금 페이지에서 최신 값을 확인하세요.)

> Blaze(종량제) 플랜으로 올리지 마세요. Spark에 머무는 한 청구서가 생기지 않습니다.

## 처음 한 번만 하는 설정

### 1. Firebase 프로젝트 만들기

1. [Firebase 콘솔](https://console.firebase.google.com)에서 **프로젝트 추가**
2. Google 애널리틱스는 **사용 안 함**으로 두어도 됩니다 (필요 없습니다)

### 2. 로그인 켜기

**Authentication → Sign-in method → 이메일/비밀번호 → 사용 설정**

"이메일 링크(비밀번호 없는 로그인)"는 꺼 두어도 됩니다.

### 3. 데이터베이스 만들기

**Firestore Database → 데이터베이스 만들기**

- 위치는 `asia-northeast3 (서울)`을 권합니다. **한 번 정하면 바꿀 수 없습니다.**
- 모드는 아무거나 골라도 됩니다. 다음 단계에서 규칙을 덮어씁니다.

### 4. 보안 규칙 붙여넣기 (중요)

**Firestore Database → 규칙** 탭에 이 저장소의 [`firestore.rules`](firestore.rules) 내용을
그대로 붙여넣고 **게시**를 누릅니다.

이게 실제 보안입니다. 테스트 모드 규칙을 그대로 두면 아무나 데이터를 읽고 쓸 수 있고,
30일 뒤에는 앱이 아예 동작하지 않습니다.

### 5. 웹 앱 등록하고 설정값 붙여넣기

1. **프로젝트 설정(⚙) → 내 앱 → 웹(`</>`) 추가**
2. 나오는 `firebaseConfig` 값을 [`js/firebase-config.js`](js/firebase-config.js)에 붙여넣습니다

```js
window.MP_FIREBASE_CONFIG = {
  apiKey: "AIza...",
  authDomain: "내프로젝트.firebaseapp.com",
  projectId: "내프로젝트",
  storageBucket: "내프로젝트.appspot.com",
  messagingSenderId: "123456789",
  appId: "1:123456789:web:abcdef"
};
```

이 값들은 **비밀이 아닙니다.** 웹 앱의 Firebase 설정은 공개되는 것이 정상이고,
접근 통제는 4단계의 보안 규칙이 서버에서 강제합니다. 그대로 깃에 커밋해도 됩니다.

### 6. 도메인 승인

**Authentication → Settings → 승인된 도메인**에 앱을 여는 주소를 추가합니다.

- GitHub Pages: `사용자이름.github.io`
- 로컬 테스트: `localhost` (보통 이미 들어 있습니다)

여기에 없는 주소에서 열면 로그인이 거부됩니다.

## 배포

GitHub Pages를 씁니다. 빌드 과정이 없어서 파일을 올리면 끝입니다.

1. 저장소 **Settings → Pages → Source: Deploy from a branch → `main` / `/ (root)`**
2. `https://사용자이름.github.io/save-my-wallet/` 로 열립니다
3. 아이폰 사파리에서 열고 **공유 → 홈 화면에 추가**

**앱을 고쳐서 다시 올릴 때는 [`sw.js`](sw.js)의 `VERSION` 값을 올려 주세요.**
그래야 이미 설치된 기기들이 새 버전을 알아채고, 앱 안에 "새 버전이 준비됐습니다" 알림이 뜹니다.

```js
var VERSION = "v2";   // -> "v3"
```

## 쓰는 법

### 로그인

처음이면 **회원가입** 탭에서 이름·이메일·비밀번호(6자 이상)를 넣습니다.
여기서 정한 이름이 함께 쓰는 사람에게 보입니다. 나중에 메뉴에서 바꿀 수 있습니다.

로그인 전에 이 기기에서 쓰던 기록이 있으면, 로그인한 뒤 계정으로 옮길지 한 번 물어봅니다.

### 여행 가계부 함께 쓰기

**만드는 쪽**

1. 여행 기간과 총액으로 예산을 만듭니다
2. 메뉴(⋯) → **여행 가계부 함께 쓰기** → **초대 코드 만들기**
3. 나온 8자리 코드를 같이 가는 사람에게 알려 줍니다 (공유 버튼으로 바로 보낼 수 있습니다)

**들어가는 쪽**

1. 로그인한 뒤 메뉴(⋯) → **여행 가계부 함께 쓰기**
2. 아래 **초대 코드로 참여**에 코드를 넣고 참여하기

이제 누가 얼마를 썼는지 서로 실시간으로 보입니다.
**요약** 탭에서는 사람별 지출과 **정산**(누가 누구에게 얼마를 주면 똑같이 나눠 낸 게 되는지)을 보여줍니다.

- 코드가 새어 나갔으면 **코드 새로 만들기** — 이전 코드는 즉시 못 쓰게 됩니다
- 더 부를 사람이 없으면 **초대 끄기** — 이미 들어온 사람은 그대로 함께 씁니다
- 예산을 만든 사람만 멤버를 내보내거나 예산을 지울 수 있습니다

### 새로고침

홈 화면에 추가한 웹앱에는 주소창이 없어서 새로고침 버튼이 없습니다.
**화면을 위에서 아래로 당기면** 새로고침됩니다. 이때 두 가지를 함께 합니다.

- 밀린 데이터를 서버와 맞춥니다
- 새로 배포된 버전이 있는지 확인합니다 (있으면 위에 "지금 받기" 띠가 뜹니다)

메뉴(⋯) → **새로고침**으로도 같은 일을 합니다.
그래도 옛 화면이 계속 보이면 메뉴 맨 아래 **앱 새로 받기 (캐시 비우기)** 를 누르세요.
캐시와 서비스 워커를 지우고 처음부터 받아옵니다. 기록은 계정에 있어서 사라지지 않습니다.

## 오프라인

인터넷이 끊겨도 앱은 열리고, 기록도 남길 수 있습니다.

- 앱 파일은 서비스 워커가 캐시해 둡니다
- 데이터는 Firestore의 로컬 캐시에서 읽습니다
- 오프라인에서 적은 내역은 큐에 쌓였다가 연결되면 알아서 올라갑니다

단, **한 번도 로그인한 적 없는 기기**에서는 처음에 인터넷이 필요합니다.

## 아이폰 상태바 (다이나믹 아일랜드)

홈 화면 웹앱에서 상태바 자리가 테마 색과 따로 놀지 않도록, 화면을 상태바 밑까지 끌어올리고
그 자리를 앱이 직접 칠합니다.

- `apple-mobile-web-app-status-bar-style` = `black-translucent`
- 안전 영역만큼 `padding-top: env(safe-area-inset-top)` (`[data-safe-top]`)
- 시계·배터리 글자색은 CSS `color-scheme`(테마별 `light`/`dark`)을 보고 iOS가 정합니다

첫 페인트 전에 `<head>`의 인라인 스크립트가 저장된 테마를 읽어 적용하기 때문에,
앱을 열 때 흰 화면이 번쩍하지 않습니다.

## 개발

빌드 도구가 없습니다. 파일을 열면 그게 앱입니다.

```bash
# 계산·데이터 함수 검증 (브라우저 없이)
node js/run-tests.node.js

# 브라우저에서 같은 검증 보기
# tests.html 열기

# 로컬 서버 (서비스 워커는 http에서만 동작합니다)
python -m http.server 8000
```

### 파일 구성

| 파일 | 하는 일 |
| --- | --- |
| `js/calc.js` | 순수 계산·포맷. 날짜, 금액, 집계, 사람별 정산 |
| `js/model.js` | 순수 데이터 모델. 정규화, 기본 카테고리, 초대 코드 |
| `js/auth.js` | Firebase 초기화, 로그인·회원가입·로그아웃 |
| `js/store.js` | Firestore 데이터 레이어. 실시간 구독 + 쓰기 |
| `js/refresh.js` | 서비스 워커 업데이트, 당겨서 새로고침 |
| `js/app.js` | 화면 렌더링과 이벤트 |
| `js/firebase-config.js` | **여기에 본인 Firebase 설정을 넣습니다** |
| `firestore.rules` | 서버가 강제하는 접근 규칙 |
| `sw.js` | 오프라인 캐시. 고칠 때 `VERSION` 올리기 |

`calc.js`와 `model.js`는 DOM도 저장소도 건드리지 않아서 node에서 그대로 테스트합니다.

### 데이터 구조 (Firestore)

```
users/{uid}                        displayName, email, theme, activeBudgetId, categories[]
budgets/{budgetId}                 name, startDate, endDate, totalAmount,
                                   ownerUid, memberUids[], members{uid:{name}}, inviteCode
budgets/{budgetId}/expenses/{id}   amount, categoryId, categoryName, categoryEmoji,
                                   memo, date, createdAt, uid, userName
invites/{code}                     budgetId, ownerUid, createdAt
```

지출에는 카테고리 이름·이모지를 함께 박아 둡니다.
같이 쓰는 사람의 카테고리 목록은 나와 다를 수 있어서, 이름을 남겨야 상대 화면에서도 제대로 보입니다.

`invites`는 한 건씩 조회만 되고 목록 조회는 규칙으로 막혀 있어서, 코드를 훑어볼 수 없습니다.
