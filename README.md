# 가계부

**내 돈은 소중하니까.**

기간과 총액을 정하면 **오늘 얼마 쓸 수 있는지** 알려주는 가계부입니다.
여행 갈 때는 초대 코드 하나로 같이 가는 사람과 하나의 가계부를 함께 씁니다.

[**앱 열기 →**](https://halfcodz.github.io/save-my-wallet/)

## 무엇이 다른가

대부분의 가계부는 **얼마 썼는지**를 보여줍니다. 다 쓴 다음에야 알게 되죠.

이 앱은 **지금 얼마 더 써도 되는지**를 보여줍니다.
기간과 총액만 정해 두면 나머지는 앱이 매일 다시 계산합니다.

<br>

## 홈 — 오늘 얼마 쓸 수 있나

```
 남은 금액
 445,000 원
 ████████░░░░░░░░░░░░░░░░░░░░░░
 155,000원 씀               600,000원

┌──────────────────────────────────────────┐
│  하루 사용 가능한 금액          120,000 원  │
├─────────────────────┬────────────────────┤
│  오늘 쓸 수 있는 돈   │  오늘 쓴 돈         │
│  85,000 원          │  35,000 원         │
└─────────────────────┴────────────────────┘
                              남은 기간 4일
```

숫자 셋이 각자 다른 질문에 답합니다.

| | 뜻 | 어떻게 나오나 |
| --- | --- | --- |
| **하루 사용 가능한 금액** | 이 페이스로 쓰면 기간을 딱 맞춘다 | 오늘 시작 시점 잔액 ÷ 오늘 포함 남은 일수 |
| **오늘 쓸 수 있는 돈** | 오늘 아직 이만큼 남았다 | 하루치 − 오늘 쓴 돈 |
| **오늘 쓴 돈** | 오늘 실제로 나간 돈 | 오늘 날짜 지출 합계 |

- **하루치는 하루 안에서 흔들리지 않습니다.** 그래야 거기서 오늘 쓴 돈을 뺀 값이 뜻을 갖습니다.
- **쓴 만큼 정확히 줄어듭니다.** 35,000원을 쓰면 오늘 쓸 수 있는 돈이 35,000원 줄어듭니다.
- **넘기면 음수로 알려줍니다.** 하루치 120,000원인데 200,000원을 썼다면 `-80,000원`, 게이지에는 빗금이 칩니다.
- **초과분은 남은 날이 나눠서 갚습니다.** 위처럼 넘겨 썼다면 내일 하루치는 93,300원으로 낮아진 채 시작합니다. 반대로 아껴 쓰면 올라갑니다.

기간이 끝나면 하루치 대신 `—`가 뜨고, 한도를 정하지 않은 가계부에서는 이 자리가 **하루 평균**으로 바뀝니다.

## 두 가지 가계부

**나의 가계부** — 평소 쓰는 것. 매달 1일에 저절로 새로 시작합니다.
한 달 한도를 정해 두면 위 계산이 돌아가고, 안 정하면 그냥 기록장이 됩니다.
달 단위가 안 맞으면 (월급날 기준 등) 기간을 직접 지정할 수도 있습니다.

**여행 예산** — 기간과 총액을 정해 두는 것. 여행이 끝나면 같이 끝납니다.
이쪽만 여러 명이 함께 쓸 수 있습니다.

둘은 상단 이름을 눌러 오갑니다. 여행 예산은 여러 개 만들어 둘 수 있습니다.

<br>

## 함께 쓰기와 정산

여행 가계부를 만든 사람이 **8자리 초대 코드**를 만들어 알려주면 끝입니다.
받은 사람은 로그인한 뒤 코드를 넣고 참여합니다.

이제 누가 얼마를 썼는지 **서로 실시간으로 보입니다.** 각자 자기 폰에서 자기가 쓴 걸 적으면 됩니다.

여행이 끝나면 **요약** 탭에서 **정산**을 봅니다.
누가 누구에게 얼마를 주면 똑같이 나눠 낸 게 되는지 알려줍니다.
많이 받을 사람과 많이 줄 사람을 큰 것부터 짝지어서 송금 횟수를 줄입니다.

- 코드가 새어 나갔으면 **코드 새로 만들기** — 이전 코드는 즉시 못 씁니다
- 더 부를 사람이 없으면 **초대 끄기** — 이미 들어온 사람은 그대로입니다
- 만든 사람만 멤버를 내보내거나 예산을 지울 수 있습니다

> 지출에는 누가 썼는지와 카테고리 이름이 함께 저장됩니다.
> 그래서 상대의 카테고리 목록이 나와 달라도 서로의 화면에서 제대로 보입니다.

<br>

## 내역 — 달력으로 먼저

내역 탭은 **달력**으로 엽니다. 어느 날 얼마를 썼는지 한눈에 보이고,
날짜를 누르면 그 칸이 카드로 자라나면서 그날 내역이 펼쳐집니다.

- 오른쪽 위 버튼으로 **리스트 보기**로 전환
- 지출을 **왼쪽으로 밀면 삭제** (손가락을 따라옵니다)
- **길게 눌러 여러 개 선택** 후 한 번에 삭제
- 지출을 저장하면 아래에 **되돌리기**가 잠깐 떠 있습니다

## 손에 붙는 것들

**홈 화면에 추가하면 앱이 됩니다.** 사파리에서 공유 → 홈 화면에 추가.
주소창 없이 전체 화면으로 뜨고, 아이폰 다이나믹 아일랜드 자리까지 테마 색이 이어집니다.

**인터넷이 끊겨도 열립니다.** 앱 파일은 캐시에, 데이터는 로컬에 있습니다.
오프라인에서 적은 내역은 연결되면 알아서 올라갑니다.

**당겨서 새로고침.** 홈 화면 웹앱에는 새로고침 버튼이 없어서, 화면을 위에서 아래로 당깁니다.
밀린 데이터를 맞추고, 새 버전이 배포됐는지도 함께 확인합니다.

**다크 모드.** 메뉴에서 전환합니다. 첫 페인트 전에 테마를 읽어서 열 때 흰 화면이 번쩍하지 않습니다.

## 비용

**전부 무료입니다. 카드 등록도 필요 없습니다.**

| 구성 | 쓰는 것 | 비용 |
| --- | --- | --- |
| 앱 배포 | GitHub Pages | 무료 (공개 저장소) |
| 로그인 | Firebase Authentication (이메일/비밀번호) | 무료 |
| 데이터 저장·실시간 동기화 | Cloud Firestore (Spark 플랜) | 무료 |

Firebase의 **Spark 플랜은 결제 수단을 등록하지 않는 무료 플랜**이라서,
한도를 넘어도 요금이 청구되지 않습니다. 한도를 넘으면 그날 요청이 거부될 뿐입니다.
"모르는 사이에 돈이 나가는" 경우가 구조적으로 생기지 않습니다.

Spark의 Firestore 하루 한도는 대략 읽기 5만 건 / 쓰기 2만 건 / 저장 1GiB입니다.
10명이 여행 하나를 함께 기록해도 하루 수백 건이라 한도의 1%도 쓰지 않습니다.
(최신 값은 Firebase 요금 페이지에서 확인하세요.)

> Blaze(종량제)로 올리지 마세요. Spark에 머무는 한 청구서가 생기지 않습니다.

## 내 걸로 띄우기

이 저장소를 포크해서 본인 Firebase에 물리면 나만의 가계부가 됩니다. 빌드 도구가 없어서, 파일을 올리면 그게 배포입니다.

<details>
<summary><b>Firebase 설정 (처음 한 번)</b></summary>

<br>

**1. 프로젝트 만들기**

[Firebase 콘솔](https://console.firebase.google.com)에서 **프로젝트 추가**.
Google 애널리틱스는 **사용 안 함**으로 두어도 됩니다.

**2. 로그인 켜기**

**Authentication → Sign-in method → 이메일/비밀번호 → 사용 설정**
"이메일 링크(비밀번호 없는 로그인)"는 꺼 두어도 됩니다.

**3. 데이터베이스 만들기**

**Firestore Database → 데이터베이스 만들기**

- 위치는 `asia-northeast3 (서울)`을 권합니다. **한 번 정하면 바꿀 수 없습니다.**
- 모드는 아무거나 골라도 됩니다. 다음 단계에서 규칙을 덮어씁니다.

**4. 보안 규칙 붙여넣기 (중요)**

**Firestore Database → 규칙** 탭에 [`firestore.rules`](firestore.rules) 내용을 그대로 붙여넣고 **게시**.

이게 실제 보안입니다. 테스트 모드 규칙을 그대로 두면 아무나 데이터를 읽고 쓸 수 있고,
30일 뒤에는 앱이 아예 동작하지 않습니다.

**5. 웹 앱 등록하고 설정값 넣기**

**프로젝트 설정(⚙) → 내 앱 → 웹(`</>`) 추가** 후, 나오는 `firebaseConfig`를
[`js/firebase-config.js`](js/firebase-config.js)에 붙여넣습니다.

```js
window.MP_FIREBASE_CONFIG = {
  apiKey: "AIza...",
  authDomain: "내프로젝트.firebaseapp.com",
  projectId: "내프로젝트",
  storageBucket: "내프로젝트.appspot.com",
  messagingSenderId: "123456789",
  appId: "1:123456789:web:abcdef"
};
```

이 값들은 **비밀이 아닙니다.** 웹 앱의 Firebase 설정은 공개되는 것이 정상이고,
접근 통제는 4단계의 보안 규칙이 서버에서 강제합니다. 그대로 커밋해도 됩니다.

**6. 도메인 승인**

**Authentication → Settings → 승인된 도메인**에 앱을 여는 주소를 추가합니다.

- GitHub Pages: `사용자이름.github.io`
- 로컬 테스트: `localhost` (보통 이미 들어 있습니다)

여기에 없는 주소에서 열면 로그인이 거부됩니다.

## 개발

빌드 도구가 없습니다. 번들러도 트랜스파일러도 npm 의존성도 쓰지 않습니다.
파일을 열면 그게 앱입니다. 구형 사파리를 염두에 두고 ES5로 씁니다.

```bash
# 계산·데이터 함수 검증 (의존성 없음)
node js/run-tests.node.js

# 앱 전체 구동 검증 (jsdom 필요, 없으면 스스로 건너뜁니다)
npm i jsdom && node js/smoke.node.js

# 브라우저에서 같은 검증 보기 → tests.html

# 로컬 서버 (서비스 워커는 http에서만 동작합니다)
python -m http.server 8000
```

`js/smoke.node.js`는 실제 `index.html`을 jsdom에 띄우고 Firebase를 메모리 가짜로 바꿔서
회원가입 → 예산 생성 → 지출 입력 → 되돌리기 → 초대 코드 → 상대 지출 동기화 → 정산 →
테마 → 로그아웃 → 재로그인 → 초대 코드로 참여까지 실제로 눌러 봅니다.

### 파일 구성

| 파일 | 하는 일 | node 검증 |
| --- | --- | --- |
| `js/calc.js` | 순수 계산·포맷. 날짜, 금액, 집계, 사람별 정산 | O |
| `js/model.js` | 순수 데이터 모델. 정규화, 기본 카테고리, 초대 코드 | O |
| `js/auth.js` | Firebase 초기화, 로그인·회원가입·로그아웃 | X |
| `js/store.js` | Firestore 데이터 레이어. 실시간 구독 + 쓰기 | X |
| `js/refresh.js` | 서비스 워커 업데이트, 당겨서 새로고침 | X |
| `js/app.js` | 화면 렌더링과 이벤트 | X |
| `js/firebase-config.js` | **여기에 본인 Firebase 설정을 넣습니다** | — |
| `firestore.rules` | 서버가 강제하는 접근 규칙 | — |
| `sw.js` | 오프라인 캐시. 고칠 때 `VERSION` 올리기 | — |

`calc.js`와 `model.js`는 DOM도 저장소도 건드리지 않아서 node에서 그대로 테스트합니다.
**계산이나 데이터 변형 로직은 되도록 이 둘에 넣습니다.**

`index.html`은 마크업만 들고 있고 `app.js`가 값을 꽂습니다.
`data-el` / `data-show` / `data-act` 훅으로 이어지며, 새 훅을 만들면 양쪽을 다 고칩니다.

### 데이터 구조 (Firestore)

```
users/{uid}                        displayName, email, theme, activeBudgetId, categories[]
budgets/{budgetId}                 name, startDate, endDate, totalAmount, createdAt,
                                   ownerUid, memberUids[], members{uid:{name}}, inviteCode
budgets/{budgetId}/expenses/{id}   amount, categoryId, categoryName, categoryEmoji,
                                   memo, date, createdAt, uid, userName
invites/{code}                     budgetId, ownerUid, createdAt
```

- 지출에 **카테고리 이름·이모지를 항상 함께** 저장합니다. 같이 쓰는 사람의 카테고리 목록은
  나와 다를 수 있어서, 이름을 안 남기면 상대 화면에서 "카테고리 없음"이 됩니다.
- 지출에 **`uid`/`userName`** 을 남깁니다. 사람별 합계와 정산이 여기에 의존합니다.
- `budget.shared`는 저장하지 않고 계산합니다 (`memberUids.length > 1 || inviteCode`).
- `invites`는 한 건씩 조회만 되고 목록 조회는 규칙으로 막혀 있어서, 코드를 훑어볼 수 없습니다.
